# Нефункциональные требования

**Статус:** `Согласовано` (2026-08-24). Дополнено решениями по отчёту `reports/incompatibility-ft-nft.md` (2026-08-24).

**Контекст:** `requirements/glossary.md`, `requirements/functional-requirements.md`  
**Источник правды:** `documentation/specification-sea-battle-v1-1.md`; закрытые решения — `requirements/answers-project.md` (Axxxx)  
**Модель качества:** ISO/IEC 25010:2023 (модель качества продукта)  
**Нумерация:** с `NFT-001`. Последний ID: `NFT-020`.

Термины и коды (`MISS`, `HIT`, `SUNK`, `GAME_OVER`, игровая сессия, десктопный клиент, серверный ИИ) — по глоссарию. Формулировки без стека и UI-решений, кроме каналов REST / WebSocket как зафиксированного контракта MVP (A0047; A0071).

**Приоритет всех НФТ = Must**, пока заказчик явно не задал иное. Колонка MoSCoW в таблицу не вводилась.

## Границы модели (7 характеристик)

В ISO/IEC 25010:2023 у модели качества продукта **9** характеристик. В эту таблицу включены **7** характеристик качества, которые задают НФТ (не поведение партии). A0042: набор подтверждён.

| № | Характеристика (EN) | Русское имя |
| --- | --- | --- |
| 1 | Performance efficiency | Эффективность производительности |
| 2 | Compatibility | Совместимость |
| 3 | Interaction capability | Способность к взаимодействию |
| 4 | Reliability | Надёжность |
| 5 | Security | Защищённость |
| 6 | Maintainability | Сопровождаемость |
| 7 | Flexibility | Гибкость |

**Не включены в таблицу (намеренно):**

- **Functional suitability** — закрывается согласованными ФТ (`FT-001` … `FT-079`), а не отдельными НФТ.
- **Safety** — в ТЗ нет вреда жизни, здоровью или имуществу; для PvE-игры «Морской бой» характеристика не применяется.

## Правила измерения

ID правил: `MR-01`…`MR-07` (Measurement Rule). Не путать с ID закрытых ответов `A0001+` в `answers-project.md`.

| ID | Содержание | Статус |
| --- | --- | --- |
| MR-01 | Контрольная нагрузка MVP: до **3** одновременных активных игровых сессий (как FT-004), каждая с одним десктопным клиентом. | Следует из ТЗ / ФТ |
| MR-02 | Сеть измерения: один хост или локальная сеть без искусственной задержки. Интернет-SLA в MVP нет. | A0047 |
| MR-03 | Процентиль **p95** считается не менее чем по **100** однотипным операциям в контрольном прогоне, если в условии не указано иное. | A0043; A0044; A0045 |
| MR-04 | Время расчёта хода серверного ИИ измеряется **на сервере**: от момента, когда право хода перешло ИИ, до момента выбранной клетки выстрела (пересчёт матрицы вероятностей + выбор клетки). Применение выстрела и доставка результата клиенту в эти 200 мс (NFT-002) не входят. | A0044; A0074 |
| MR-05 | Время ответа на выстрел игрока измеряется **на клиенте**: от отправки выстрела по WebSocket до получения результата `MISS` / `HIT` / `SUNK`. Отказы в эту выборку не входят (NFT-006, NFT-019). | A0043 |
| MR-06 | Пороги времени в таблице — согласованные значения (A0043, A0044, A0045, A0053, A0054, A0055). | A0043; A0044; A0045; A0053; A0054; A0055 |
| MR-07 | Выборки в условиях NFT-003 (≥ 3 пары сессий), NFT-004 (≥ 10 партий), NFT-006 (≥ 20 отказов каждого класса), NFT-007 (≥ 10 циклов возобновления), NFT-009 (≥ 5 партий), NFT-010 (≥ 20 попыток каждого вида), NFT-014 (≥ 3 полных партий) — обязательный минимум прогона. Меньший объём не засчитывается. | A0056 |

## Вне MVP / вне scope

- Целевая доступность 24/7, процент uptime (A0052), SLA в интернете (A0047), CDN, горизонтальное масштабирование сверх 3 сессий.
- Лимит времени на ход игрока (A0050); обрыв партии — idle TTL 30 минут (FT-005, FT-053). Выход на ходе игрока = сдача (FT-077), не как отдельный НФТ.
- Клиент на Linux и macOS (A0046).
- Идентификация игрока, аутентификация, роли, персональные данные (логин вне MVP); доступ к партии — по идентификатору сессии (A0048).
- PvP, ручная расстановка, рейтинг.
- Functional suitability и Safety как отдельные НФТ (A0042).
