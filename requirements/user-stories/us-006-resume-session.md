# US-006: Возобновить партию (автовозобновление соединения того же запуска)

## User Story

```text
As a Игрок,
I want после обрыва соединения в том же запуске Фронтенда автоматически возобновить партию, пока не истёк idle TTL, и видеть оставшееся время TTL,
So that я могу продолжить матч без ручного ввода идентификатора сессии.
```

**Статус:** `Черновик, требует согласования`  
**Приоритет (MoSCoW):** Should  
**Источник:** A0001; A0002; A0023; A0093; A0094; A0097; A0104; A0107  
**Связанные ФТ:** FT-002, FT-005, FT-053, FT-054, FT-066, FT-067, FT-068, FT-074, FT-080

## Acceptance Criteria (Gherkin)

### AC1 — Автовозобновление соединения в том же запуске

```gherkin
Given существует активная игровая сессия, у которой idle TTL ещё не истёк
And к сессии нет другого активного соединения Фронтенда
And Фронтенд всё ещё в том же запуске, где сессия была создана или уже подключена
When соединение обрывается и Фронтенд восстанавливает канал
Then система возвращает актуальное оперативное состояние (матрицы полей, история выстрелов, текущий ход)
And это считается возобновлением, а не вторым Фронтендом
And возобновление само по себе не сдвигает idle TTL
And отдельного экрана ввода идентификатора сессии в MVP нет (A0093)
```

### AC2 — Один активный Фронтенд на сессию

```gherkin
Given к игровой сессии уже есть активное соединение Фронтенда
When второй экземпляр Фронтенда пытается подключиться с тем же идентификатором
Then система отклоняет подключение второго Фронтенда
And первый Фронтенд продолжает удерживать сессию
```

### AC3 — Показ оставшегося idle TTL

```gherkin
Given у Игрока активная игровая сессия во Фронтенде
When он смотрит на экран партии
Then Фронтенд показывает оставшееся время idle TTL (A0094, FT-080)
```

### AC4 — Edge case: отказ, TTL, перезапуск приложения

```gherkin
Given идентификатор сессии неизвестен
  Or сессия недоступна
  Or idle TTL 30 минут истёк и состояние удалено
  Or сессия удалена после сбоя heatmap (FT-075)
When Фронтенд пытается возобновить соединение
Then система отвечает единым отказом «сессия недоступна» без различия этих случаев для Фронтенда (A0001, A0097)
And при удалении по TTL Фронтенд (если был связан) получает оповещение об истечении TTL
And удаление по TTL не фиксирует GAME_OVER и не меняет статистику

Given партия была активна, но Игрок полностью перезапустил приложение
When он открывает Фронтенд снова
Then в MVP нет возобновления этой сессии через ввод id или автовозобновление соединения прошлого запуска (A0093, A0104)
And если состояние ещё хранится на Бэкенде, слот лимита сессий занимает его до TTL или явного завершения по другим правилам
```
