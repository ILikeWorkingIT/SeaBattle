# Глоссарий проекта Sea Battle

**Статус:** `Черновик, требует согласования`

**Источник правды:** `documentation/specification-sea-battle-v1-1.md`  
Правила игры в ТЗ опираются на канон «Морской бой» (Russian standard rules) и не подменяются другими вариантами правил.

**Где хранится файл:** `requirements/glossary.md` (по структуре проекта).

## 1. Система и роли

| Термин | Синонимы / EN | Определение | Источник |
| --- | --- | --- | --- |
| Sea Battle | Морской бой (в названии проекта) | Клиент-серверная распределенная игровая система, реализующая пошаговую игру «Морской бой» в режиме игрок против серверного ИИ. | ТЗ, §1 |
| PvE | Игрок против серверного ИИ | Режим игры: человек играет против серверного ИИ, а не против другого человека. | ТЗ, §1 |
| Игрок | — | Человек-участник партии. Игру начинает игрок. | ТЗ, §3.3 |
| Серверный ИИ | бот, Heatmap Bot | Алгоритм на сервере, который перед каждым своим выстрелом считает матрицу вероятностей и выбирает клетку для выстрела. | ТЗ, §1, §4 |
| Десктопный клиент | клиент | Настольное приложение игрока. Одновременно допускается не более трёх активных игровых сессий. | ТЗ, §1, §2.3; решение заказчика 2026-08-24 |
| Игровая сессия | Game Session, матч | Оперативное состояние активной партии: матрицы полей, история выстрелов, текущий ход. Хранится со скользящим idle TTL 30 минут. TTL сдвигают только создание сессии и выстрел (возобновление, смена языка, запрос статистики — нет). Термины «игровая сессия» и «матч» обозначают один объект. Пока TTL не истёк, сессию можно возобновить по идентификатору. В MVP идентификатор сессии — единственный секрет доступа к партии (логина нет). Неизвестный или недоступный id даёт единый отказ без различия этих случаев. К одной сессии одновременно — не более одного активного соединения клиента; после обрыва повторное подключение по id — возобновление, не второй клиент. Обрыв не освобождает слот лимита сессий, пока состояние хранится и TTL не истёк. На своём ходе игрок либо стреляет, либо выходит (= сдаётся): выход фиксирует `GAME_OVER` с победой серверного ИИ. | ТЗ, §2.2; решение заказчика 2026-08-24 |
| Матч | игровая сессия | Синоним игровой сессии. | Решение заказчика 2026-08-24 |
| Участник | — | Сторона партии (игрок или серверный ИИ), у которой есть свой флот. Победа наступает при уничтожении флота одного из участников. | ТЗ, §3.3 |
| Язык интерфейса | — | Русский или английский. При первом запуске берётся язык ОС, если это RU или EN; иначе английский. Смена пунктом меню сразу меняет только подписи экрана: без пересоздания игровой сессии и без смены кодов клеток в состоянии; выбранный язык сохраняется для следующих запусков. | ТЗ, §5; решение заказчика 2026-08-24 |

## 2. Поле, флот, расстановка

| Термин | Синонимы / EN | Определение | Источник |
| --- | --- | --- | --- |
| Игровое поле | поле | Квадратная матрица 10×10 клеток. У каждого участника своё поле. | ТЗ, §3.1 |
| Клетка | — | Единица поля. Может быть целью выстрела и частью палубы корабля или пустой. | ТЗ, §3.1–3.3 |
| Координаты клетки | код клетки | На экране буквы зависят от языка интерфейса: русский — А–К (без «Ё» и «Й»); английский — A–J. Число 1–10. Во фронте, на бэке и в хранилище — двухцифровой код «столбец-строка». Индекс столбца: А/A=0 … К/J=9. Индекс строки: 1=0 … 10=9. Пример: А3 и A3 → `02`. | ТЗ, §3.1, §5; решение заказчика 2026-08-24 |
| Корабль | — | Прямолинейная фигура из одной или нескольких палуб. Не пересекается и не соприкасается с другими кораблями сторонами и углами. | ТЗ, §3.1–3.2 |
| Палуба | — | Одна клетка корабля. У каждого участника 20 палуб на 10 кораблей. | ТЗ, §3.1 |
| Флот | состав флота | Набор кораблей одного участника: 1 линкор, 2 крейсера, 3 эсминца, 4 катера (итого 10 кораблей / 20 палуб). | ТЗ, §3.1 |
| Линкор | четырёхпалубный | Корабль длины 4. В флоте: 1 штука. | ТЗ, §3.1 |
| Крейсер | трёхпалубный | Корабль длины 3. В флоте: 2 штуки. | ТЗ, §3.1 |
| Эсминец | двухпалубный | Корабль длины 2. В флоте: 3 штуки. | ТЗ, §3.1 |
| Катер | однопалубный | Корабль длины 1. В флоте: 4 штуки. | ТЗ, §3.1 |
| Расстановка | генерация полей | Размещение флота на поле. Только горизонталь или вертикаль. Минимальная дистанция между любыми точками разных кораблей — 1 пустая клетка. В проекте расстановку игрока и бота выполняет сервер псевдослучайно с проверкой правил. | ТЗ, §3.2, §2.1 |
| Буферная зона | периметр потопленного корабля | Клетки вокруг потопленного корабля. После `SUNK` получают статус `MISS`. Другие корабли там быть не могут. | ТЗ, §3.3; решение заказчика 2026-08-24 |

## 3. Ход боя и исходы выстрела

Коды в скобках — формулировки ТЗ. Их нужно использовать единообразно в требованиях и дальнейшем API.

| Термин | Код / синоним | Определение | Источник |
| --- | --- | --- | --- |
| Ход | выстрел, право хода | Действие стороны: выбор клетки для выстрела. После промаха право хода переходит сопернику. После попадания или потопления стреляющий ходит снова. | ТЗ, §3.3 |
| Стреляющий | — | Сторона, которая только что выполнила выстрел. | ТЗ, §3.3 |
| Промах | `MISS` | Выстрел в клетку без палубы. Клетка помечается как проверенная. Право хода переходит к противоположной стороне. | ТЗ, §3.3 |
| Попадание | `HIT`, ранен | Один результат выстрела: палуба повреждена, корабль ещё не уничтожен целиком. «Попадание» и «ранен» не разделяются. Стреляющий сохраняет право хода. | ТЗ, §3.3; решение заказчика 2026-08-24 |
| Потоплен | `SUNK` | Все палубы корабля уничтожены. Клетка последней палубы входит в состав потопленного корабля со статусом `SUNK` (отдельного кода нет). Периметр корабля помечается как «промах/пусто». Стреляющий сохраняет право хода. Если уничтожен весь флот, отдельно фиксируется `GAME_OVER`. | ТЗ, §3.3; решение заказчика 2026-08-24 |
| Победа | `GAME_OVER` | Уничтожены все 10 кораблей (20 палуб) одного участника. | ТЗ, §3.3 |
| История выстрелов | — | Часть оперативного состояния сессии вместе с матрицами полей и текущим ходом. | ТЗ, §2.2 |
| Оповещение о смене состояния | — | Доставка десктопному клиенту одним набором событий: смена права хода, результат выстрела (`MISS` / `HIT` / `SUNK`) любой стороны, наступление `GAME_OVER`, событие выстрела серверного ИИ. Истечение idle TTL — отдельное оповещение. Создание сессии сообщается в ответе на запрос создания, без отдельного push. Сбой пустой heatmap при живом флоте игрока — отдельное сообщение о сбое. | ТЗ, §2.1; решение заказчика 2026-08-24 |

## 4. Серверный ИИ (Heatmap Bot)

| Термин | Синонимы / EN | Определение | Источник |
| --- | --- | --- | --- |
| Матрица вероятностей | Heatmap, Probability Density Map | Матрица 10×10, которую бот пересчитывает перед каждым своим выстрелом. Клетка с максимальным весом — кандидат на выстрел; при равенстве весов выбор случайный из лидеров. | ТЗ, §1, §4 |
| Режим поиска | Hunt Mode | Режим, пока нет раненого не потопленного корабля. Для свободных клеток считается, сколькими способами через них ещё можно поставить оставшиеся корабли, с учётом промахов и потопленных зон. Приоритет — клетки с наибольшим весом. | ТЗ, §4 |
| Режим добивания | Target Mode | Режим при раненом, но не потопленном корабле. При одном `HIT` релевантны непроверенные ортогональные соседи (крест). При двух и более `HIT` на линии релевантны только продолжения этой оси до края поля или до `MISS`. Вес остальных клеток — 0. Если ранены несколько кораблей, ИИ добивает один до `SUNK`, затем следующий. | ТЗ, §4; решение заказчика 2026-08-24 |
| Оставшиеся корабли | нерассмотренные корабли на плаву | Корабли игрока, которые ещё не потоплены; для расчёта heatmap используются длины всех таких кораблей с учётом количества. | ТЗ, §4; решение заказчика 2026-08-24 |
| Сбой пустой heatmap | — | Нет свободных клеток с ненулевым весом, а флот игрока ещё не уничтожен. Партия останавливается без выстрела и без статистики; клиент получает сообщение о сбое. | Решение заказчика 2026-08-24 |

## 5. Аналитика (как названо в ТЗ)

| Термин | Определение | Источник |
| --- | --- | --- |
| Глобальная статистика | Счётчики на весь сервер (в MVP не разделяются по игрокам): всего игр, побед игрока, побед ИИ, среднее число выстрелов. Меняются только при `GAME_OVER` (включая сдачу / выход игрока на своём ходе). «Ход» для среднего — один выстрел. При нуле завершённых партий среднее = 0. Оборванная партия и истечение TTL не входят. | ТЗ, §2.2; решение заказчика 2026-08-24 |

## 6. Открытые вопросы

Закрыто решением заказчика (2026-08-24), включая анализ несовместимостей: сессия = матч; TTL сдвигают только создание и выстрел; переподключение по id ≠ второй клиент; буфер = `MISS` (хранить и отдавать); Target Mode — добивать один корабль; heatmap с кратностью длин; пустая heatmap при живом флоте — сбой; статистика только при `GAME_OVER`, при 0 игр среднее = 0; на ходе игрока выстрел или выход (= сдача, победа ИИ); оповещения — канон FT-036. Открыто: пояснение по FT-063 (заказчик не понял вопрос).

## 7. Правило использования

В требованиях, user stories и use cases использовать термины и коды из этого файла (`MISS`, `HIT`, `SUNK`, `GAME_OVER`, Hunt Mode, Target Mode) и не заменять их бытовыми синонимами без записи в глоссарий.
