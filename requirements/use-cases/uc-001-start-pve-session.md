# UC-001: Начать партию против Бэкенда (PvE)

**Статус артефакта:** `Согласовано`, 2026-08-25 (A0146)  
**Уровень:** user goal  
**Связанные US:** US-001  
**Связанные ФТ:** FT-001, FT-004, FT-006, FT-009, FT-010, FT-011, FT-012, FT-013, FT-014, FT-015, FT-016, FT-043, FT-049, FT-050, FT-069  
**Источники:** ТЗ §1, §2.1, §3.1–3.2; A0012; A0081; A0087; A0114; A0146; A0115; A0122; A0123; NFT-015

---

## 1. Акторы

| Роль | Тип | Участие |
| --- | --- | --- |
| Игрок | Primary | Запрашивает начало партии |
| Фронтенд | Supporting | Передаёт запрос создания сессии (REST), показывает расстановку |
| Бэкенд | Supporting | Создаёт сессию, генерирует оба флота, выдаёт расстановку Игрока |

---

## 2. Предусловие

- Фронтенд запущен и может обратиться к Бэкенду.
- Режим партии — только PvE (игрок против Бэкенда).
- На Бэкенде допускается **не более трёх** активных игровых сессий одновременно (0…3; FT-004). Три активные сессии — допустимое состояние системы.
- Для **успешного** создания ещё одной сессии в основном потоке: сейчас занято не больше двух слотов (0…2). Если уже заняты все три — отказ по FT-049 (см. альтернативы), без четвёртой сессии.

---

## 3. Триггер

Игрок через Фронтенд запрашивает начало новой партии.

---

## 4. Основной поток

1. Фронтенд отправляет Бэкенду запрос создания игровой сессии.
2. Бэкенд проверяет лимит FT-004: если активных сессий уже три — отказ (альтернатива [Шаг 2.3]); иначе (0…2) продолжает создание. После успеха итог по-прежнему ≤ 3, в том числе ровно 3, если до запроса было 2.
3. Бэкенд псевдослучайно генерирует расстановку флота Игрока и флота Бэкенда (10 кораблей / 20 палуб каждый; горизонталь/вертикаль; дистанция ≥ 1 клетка включая углы) и при необходимости повторяет генерацию до первой валидной пары в пределах окна создания сессии (NFT-015 / FT-010).
4. Бэкенд создаёт игровую сессию, сохраняет оперативное состояние, передаёт право первого хода Игроку и учитывает сессию в лимите активных сессий (итог 1…3).
5. Бэкенд выдаёт Фронтенду расстановку флота Игрока и идентификатор сессии; расстановку Бэкенда и матрицу вероятностей не передаёт.
6. Фронтенд отображает поле Игрока и скрытое поле Бэкенда; партия готова к выстрелу Игрока (переход к UC-002).
7. Бэкенд фиксирует сдвиг idle TTL от момента успешного создания сессии.

---

## 5. Альтернативные потоки

### 5.1. Некорректные данные

**[Шаг 1.1]** Запрос создания сессии без обязательных полей контракта или с неверным типом полезной нагрузки.

1. Бэкенд отклоняет запрос без создания сессии и без занятия слота лимита.
2. Фронтенд показывает отказ старта.
3. **Завершение** сценария (сессия не создана; статистика не меняется).

### 5.2. Timeout / недоступность

**[Шаг 1.2]** Бэкенд недоступен или ответ на создание сессии не получен в разумное для Фронтенда время ожидания.

1. Фронтенд не получает расстановку Игрока.
2. Сессия на стороне Бэкенда либо не создана, либо (если создание началось, но клиент не подтвердил готовность) не занимает слот до успешной выдачи расстановки (FT-010, A0081).
3. Фронтенд различает таймаут и отказ Бэкенда для логов/повтора; Игроку показывает короткое сообщение («сервер не ответил» или текст отказа), без деталей генерации (A0123).
4. **Завершение** сценария. Игрок может повторить запрос (возврат к шагу 1 основного потока при новой попытке).

**[Шаг 3.1]** За окно создания сессии валидная расстановка не получена (таймаут генерации / NFT-015).

1. Бэкенд отказывает в создании единым сообщением об ошибке старта.
2. Сессия не создаётся; слот лимита не занимается; статистика не меняется.
3. **Завершение** сценария.

### 5.3. Прерывание

**[Шаг 1.3]** Игрок отменяет ожидание старта на Фронтенде (закрывает диалог / уходит с экрана) до получения ответа.

1. Фронтенд прекращает ожидание ответа на UI.
2. Если Бэкенд уже успел завершить успешный старт — сессия может остаться активной на сервере до TTL (см. UC-006); иначе сессии нет.
3. **Завершение** с точки зрения текущего UI-сценария. Повторный старт — новый запуск основного потока с шага 1.

### 5.4. Недостаточно прав

**Не применимо.** В MVP нет логина и RBAC: доступ к созданию партии не разграничивается ролями (A0016). Отказы — по лимиту сессий и валидности запроса, не по «правам пользователя».

### 5.5. Конкурентный доступ

**[Шаг 2.1]** Параллельно с запросом Игрока уже заняты три слота (гонка с другими Фронтендами / сессиями).

1. Бэкенд атомарно отказывает в создании четвёртой сессии (FT-049) с отдельным кодом отказа (A0087, A0122).
2. Слот не занимается; статистика не меняется.
3. Фронтенд показывает сообщение об отказе; отдельного UX автоповтора старта в MVP нет (A0115).
4. **Завершение** сценария. Игрок может повторить позже вручную (шаг 1).

### 5.6. Граничные значения

**[Шаг 2.2]** Уже есть ровно две активные сессии — запрос успешен; после создания становится ровно три (верхняя допустимая граница FT-004).

1. Основной поток продолжается с шага 3.

**[Шаг 2.3]** Уже есть ровно три активные сессии (лимит исчерпан) — четвёртую создать нельзя.

1. Как [Шаг 2.1]: отказ FT-049, **завершение**.

**[Шаг 3.2]** Граница поля и состава флота: генерация обязана дать ровно 10×10, состав 1+2+3+4 корабля; при нарушении правил расстановки генерация повторяется до валидной (шаг 3), а не выдаёт невалидное поле.

## 6. Потоки исключений

### E1. Сбой выдачи после генерации

На шаге 4–5 внутренний сбой Бэкенда после генерации, но до подтверждённой выдачи расстановки Игроку.

1. Бэкенд не учитывает сессию в лимите (слот не занят) либо откатывает незавершённый старт (A0081 / FT-010).
2. Фронтенд получает единое сообщение об ошибке старта.
3. **Завершение.** Выстрел до успешного старта отклоняется (FT-069).

### E2. Утечка скрытых данных при старте

На шаге 5 обнаружена попытка/ошибка передачи Фронтенду расстановки Бэкенда или heatmap.

1. Такой ответ недопустим (FT-015, FT-050, NFT-009).
2. Корректная реализация не отдаёт скрытые данные; при сбое выдачи — откат к E1 / ошибке старта.
3. **Завершение** или повтор основного потока с шага 1 после исправления.

---

## 7. Постусловие

**Успех:** создана активная игровая сессия PvE; Игрок получил свою расстановку; право хода у Игрока; сессия учтена в лимите (≤ 3); скрыты флот Бэкенда и heatmap; статистика не изменена; idle TTL отсчитывается от создания.

**Отказ:** сессия не создана; слот не занят; статистика не изменена; Игрок информирован об ошибке или лимите.
