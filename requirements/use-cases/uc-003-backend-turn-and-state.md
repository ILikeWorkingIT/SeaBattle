# UC-003: Ход Бэкенда и оповещение о смене состояния

**Статус артефакта:** `Согласовано`, 2026-08-25 (A0146)  
**Уровень:** user goal (ценность для Игрока) / system (исполнитель — Бэкенд)  
**Связанные US:** US-003  
**Связанные ФТ:** FT-027, FT-028, FT-029, FT-030, FT-031, FT-032, FT-033, FT-034, FT-036, FT-050, FT-052, FT-058, FT-064, FT-065, FT-075, FT-076, FT-079  
**Источники:** ТЗ §2.1, §4; A0009; A0095; A0106; A0114; A0146; A0117; A0126; A0127; NFT-002

**Связанные сценарии:** при `MISS` ход возвращается Игроку (UC-002); при уничтожении флота Игрока или победе по FT-052 — include UC-004; при сбое пустой heatmap — исключение E1.

---

## 1. Акторы

| Роль | Тип | Участие |
| --- | --- | --- |
| Бэкенд | Primary (системный) | Считает heatmap, выбирает клетку, стреляет, формирует события |
| Игрок | Interested | Получает результат через Фронтенд; не видит heatmap и подсказки Hunt/Target |
| Фронтенд | Supporting | Принимает оповещения, обновляет поле Игрока |

---

## 2. Предусловие

- Активная игровая сессия; партия не завершена.
- Право хода у Бэкенда (обычно после `MISS` Игрока в UC-002).
- Флот Игрока ещё не уничтожен **или** проверка победы выполняется в ветке пустой heatmap (FT-052).

---

## 3. Триггер

Право хода перешло Бэкенду, и Бэкенд начинает свой ход.

---

## 4. Основной поток

1. Бэкенд определяет режим: Hunt Mode (нет раненого непотопленного корабля Игрока) или Target Mode (есть ранение; при нескольких раненых — добивает один до `SUNK` по FT-079).
2. Бэкенд пересчитывает матрицу вероятностей 10×10 с учётом оставшихся кораблей, промахов и потопленных зон (область Target Mode — по FT-058).
3. Бэкенд выбирает клетку с максимальным весом; при равенстве — случайно из лидеров (FT-034, FT-064).
4. Бэкенд выполняет выстрел по полю Игрока и фиксирует `MISS`, `HIT` или `SUNK` (с буфером при `SUNK`).
5. Бэкенд обновляет состояние, сдвигает idle TTL и право хода: при `MISS` — Игроку; при `HIT`/`SUNK` — остаётся у Бэкенда (возможен повтор шагов 1–7).
6. Если уничтожена последняя палуба флота Игрока — include UC-004 (`GAME_OVER`, победа Бэкенда).
7. Бэкенд оповещает Фронтенд о событии выстрела Бэкенда, результате и смене права хода / `GAME_OVER` (FT-036; доставка at-least-once с идемпотентностью по id события — A0127). Матрица вероятностей и режимы Hunt/Target Игроку не показываются (FT-050, A0095). Фронтенд показывает явную анимацию «ход Бэкенда» без блокировки UI сверх NFT-005 / NFT-018 (A0117).

---

## 5. Альтернативные потоки

### 5.1. Некорректные данные

**Не применимо к входу Игрока.** Ход инициирует Бэкенд по своему состоянию. Внутренне некорректное состояние поля (нет валидной клетки при ненулевых весах) обрабатывается как пустая heatmap (5.6 / E1), а не как «ошибка ввода Игрока».

### 5.2. Timeout / недоступность

**[Шаг 7.1]** Фронтенд отключён в момент оповещения.

1. Бэкенд сохраняет состояние сессии; слот лимита не освобождается (FT-074).
2. Обрыв ≠ сдача.
3. При восстановлении соединения того же запуска — UC-006; Игрок получает актуальное состояние, включая уже применённый ход Бэкенда.
4. **Завершение** доставки UI; доменный ход уже применён. Основной поток для домена завершён на шаге 5–6.

**[Шаг 2.1]** Расчёт heatmap превышает целевой бюджет (NFT-002: p95 ≤ 200 мс) — требование качества, не отдельный бизнес-отказ: ход всё равно должен завершиться выбором клетки или веткой пустой heatmap.

### 5.3. Прерывание

**[Шаг 1.1]** Во время хода Бэкенда Игрок явно сдаётся (UC-005, A0092).

1. До фиксации выстрела Бэкенда в состоянии принятая сдача отменяет выстрел и даёт `GAME_OVER` с победой Бэкенда (A0126; include UC-004).
2. Если выстрел уже зафиксирован — сначала исход выстрела, затем сдача к новому состоянию (или no-op при уже `GAME_OVER`).
3. **Завершение** через UC-005 → UC-004 либо продолжение после выстрела.

**[Шаг 1.2]** Истекает idle TTL до или во время ожидания хода.

1. Сессия удаляется без `GAME_OVER` и без статистики (FT-053); оповещение FT-066 при возможности.
2. **Завершение** партии без победителя в статистике.

### 5.4. Недостаточно прав

**[Шаг 4.1]** Попытка выполнить «выстрел Бэкенда» от имени внешнего клиента / не из серверной логики хода.

1. Внешний выстрел по полю Игрока клиентом не допускается правилами партии (стреляет только Бэкенд на своём ходе).
2. Запрос Игрока в этот момент — отказ FT-046 (нет права хода).
3. **Возврат** к ожиданию завершения хода Бэкенда / шагу 1–7.

### 5.5. Конкурентный доступ

**[Шаг 4.2]** Параллельные сессии: ход в сессии A не меняет состояние сессии B (FT-003, NFT-003).

1. Обработка изолирована по идентификатору сессии.
2. **Возврат** / продолжение основного потока своей сессии.

### 5.6. Граничные значения

**[Шаг 2.2]** Все свободные клетки имеют вес 0 (пустая heatmap).

1. Выстрел не выполняется (FT-065).
2. Сначала проверка победы Бэкенда (FT-052):
   - если флот Игрока уничтожен — include UC-004;
   - иначе — исключение E1 (`SESSION_ABORTED`).
3. **Завершение** ветки без шагов 4–5 основного потока.

**[Шаг 1.3]** Target Mode: один `HIT` — крест; два+ `HIT` на линии — только продолжения оси (FT-058). Далее шаг 2.

**[Шаг 5.1]** После `HIT`/`SUNK` без `GAME_OVER` — **возврат** к шагу 1 того же UC (серия ходов Бэкенда).

---

## 6. Потоки исключений

### E1. Сбой пустой heatmap при живом флоте Игрока (A0106)

1. Выстрел не выполняется.
2. Фронтенд сначала получает `SESSION_ABORTED` и текст RU/EN о прерывании и необходимости новой партии (FT-076).
3. Затем состояние удаляется, слот освобождается, статистика не меняется (FT-075).
4. Последующее возобновление — единый отказ «сессия недоступна» (FT-067).
5. **Завершение.** Новая партия — только UC-001.

### E2. Ошибка формирования оповещения после успешного выстрела

1. Состояние на Бэкенде уже изменено; при восстановлении канала Игрок получает снимок по UC-006.
2. **Возврат** к согласованному состоянию через возобновление, без повторного применения того же выстрела.

---

## 7. Постусловие

**Успех с `MISS`:** ход у Игрока; поле Игрока обновлено; Фронтенд оповещён (если был на связи); heatmap скрыта.

**Успех с `HIT`/`SUNK`:** ход у Бэкенда; возможен повтор UC-003; либо UC-004 при конце флота.

**Сбой heatmap:** сессии нет; статистики нет; Игрок уведомлён о `SESSION_ABORTED`.

**TTL:** сессии нет; `GAME_OVER` нет.
