# UC-004: Завершить партию (GAME_OVER) и обновить статистику

**Статус артефакта:** `Согласовано`, 2026-08-25 (A0146)  
**Уровень:** subfunction / extension (вызывается из UC-002, UC-003, UC-005)  
**Связанные US:** US-004  
**Связанные ФТ:** FT-025, FT-026, FT-038, FT-039, FT-040, FT-041, FT-047, FT-056, FT-071  
**Источники:** ТЗ §2.2, §3.3; A0005; A0027; A0088; A0103; A0114; A0146; A0118; A0128; A0129

---

## 1. Акторы

| Роль | Тип | Участие |
| --- | --- | --- |
| Бэкенд | Primary (системный) | Фиксирует `GAME_OVER`, победителя, запись статистики |
| Игрок | Interested | Получает исход через Фронтенд |
| Фронтенд | Supporting | Показывает результат партии |

---

## 2. Предусловие

- Существует активная (ещё не завершённая) игровая сессия **или** только что выполнен исход, требующий фиксации конца (последняя палуба / сдача / победа по FT-052).
- Причина вызова известна: уничтожение флота участника **или** явная сдача (UC-005).

---

## 3. Триггер

Наступило одно из:

- выстрел уничтожил последнюю палубу последнего корабля флота (часто вместе с `SUNK`, FT-071);
- при пустой heatmap проверка FT-052 подтвердила уничтожение флота Игрока;
- Игрок явно сдался (UC-005).

---

## 4. Основной поток

1. Бэкенд фиксирует `GAME_OVER` и определяет победителя: противоположная сторона при уничтожении флота; при сдаче — всегда Бэкенд.
2. Бэкенд запрещает дальнейшие выстрелы в этой партии (FT-047).
3. Бэкенд в одной атомарной операции (A0129) сохраняет запись завершённой партии (A0088, A0103) и обновляет глобальную статистику: число игр; победы Игрока или Бэкенда; пересчёт среднего числа выстрелов по записям (FT-038…FT-041, FT-056). При сбое записи статистики — повтор записи без второго `GAME_OVER`.
4. Бэкенд оповещает Фронтенд о `GAME_OVER` и победителе (в составе перечня FT-036).
5. Фронтенд показывает экран результата; отдельное длительное хранение снимка партии для просмотра в MVP не требуется — далее новая партия, статистика или закрытие Фронтенда (A0118).
6. Последующие запросы выстрела / повторной сдачи не меняют состояние завершённой партии и не создают второй `GAME_OVER`.
7. Слот лимита активных сессий (FT-004) освобождается **сразу** при фиксации `GAME_OVER` на Бэкенде (A0128); ACK клиента и отдельный TTL «завершённых» не требуются.

---

## 5. Альтернативные потоки

### 5.1. Некорректные данные

**[Шаг 1.1]** Повторный вызов фиксации `GAME_OVER` для уже завершённой партии (повторная сдача, повторный выстрел).

1. Новый `GAME_OVER` и повторная запись статистики **не** создаются.
2. Выстрел отклоняется (FT-047); повторная сдача не фиксируется (FT-077).
3. **Завершение** без изменения агрегатов.

### 5.2. Timeout / недоступность

**[Шаг 4.1]** Фронтенд не получает оповещение о `GAME_OVER` из-за обрыва.

1. На Бэкенде исход и статистика уже зафиксированы.
2. При попытке возобновления: сессия завершена / недоступна для продолжения боя — единый отказ либо снимок «уже GAME_OVER» по контракту Бэкенда.
3. **Завершение** доменного сценария успешно; UI может показать исход после перезапроса состояния / статистики (UC-007).

### 5.3. Прерывание

**Не применимо как отмена `GAME_OVER`.** После наступления условия конца исход необратим. Обрыв соединения не отменяет уже зафиксированный `GAME_OVER`.

### 5.4. Недостаточно прав

**[Шаг 3.1]** Попытка Фронтенда произвольно изменить счётчики статистики.

1. Запрещено (матрица прав): писать статистику может только Бэкенд при `GAME_OVER`.
2. **Завершение** отказа; агрегаты не меняются этим запросом.

### 5.5. Конкурентный доступ

**[Шаг 1.2]** Гонка двух причин конца (например, почти одновременные сдача и выстрел).

1. Бэкенд применяет ровно один исход `GAME_OVER` и одну запись статистики.
2. Второй запрос обрабатывается как [Шаг 1.1].
3. **Завершение** с одним победителем.

### 5.6. Граничные значения

**[Шаг 3.2]** До этого события не было завершённых партий — среднее число выстрелов после первой записи считается по одной записи; при нуле записей до события среднее было 0.

**[Шаг 3.3]** Победа Игрока vs победа Бэкенда — увеличивается соответствующий счётчик; число игр +1 в обоих случаях.

**[Шаг 1.3]** `SUNK` последней палубы и `GAME_OVER` — в одном исходе (FT-071), без второго «хода» статистики.

---

## 6. Потоки исключений

### E1. Сбой записи статистики после фиксации GAME_OVER в состоянии сессии

1. Предпочтительно атомарная фиксация с записью (A0129). Если запись статистики не удалась — повторить запись без второго `GAME_OVER` и без двойного начисления.
2. Игроку исход партии уже может быть показан (A0118).
3. **Завершение** с эскалацией на сопровождение при устойчивом сбое; повторный пользовательский «дожимать GAME_OVER» не допускается ([Шаг 1.1]).

### E2. Попытка начислить статистику без GAME_OVER (TTL, обрыв, SESSION_ABORTED)

1. Такие события **не** входят в этот UC (FT-053, FT-075): статистика не меняется.
2. **Завершение** без вызова основного потока UC-004.

---

## 7. Постусловие

**Успех:** партия завершена; победитель зафиксирован; есть ровно одна запись статистики на этот исход; слот FT-004 освобождён сразу; Фронтенд показывает экран результата без обязательного долгого снимка; дальнейшие ходы отклоняются.

**Неуспех вызова (уже было GAME_OVER):** состояние и статистика без повторного изменения.
