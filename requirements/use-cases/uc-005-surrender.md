# UC-005: Сдаться / явно выйти из незавершённой партии

**Статус артефакта:** `Согласовано`, 2026-08-25 (A0146)  
**Уровень:** user goal  
**Связанные US:** US-005  
**Связанные ФТ:** FT-077, FT-025, FT-026, FT-056, FT-040  
**Источники:** A0092; A0100; A0114; A0146; A0119; A0130; A0131

**Связанные сценарии:** всегда include UC-004 при успешной сдаче.

---

## 1. Акторы

| Роль | Тип | Участие |
| --- | --- | --- |
| Игрок | Primary | Запрашивает явный выход (= сдача) |
| Фронтенд | Supporting | Передаёт запрос сдачи, показывает исход |
| Бэкенд | Supporting | Фиксирует `GAME_OVER` с победой Бэкенда |

---

## 2. Предусловие

- Существует незавершённая игровая сессия (нет `GAME_OVER`).
- Запрос — именно явный выход, а не обрыв соединения.

---

## 3. Триггер

Игрок через Фронтенд явно запрашивает выход из незавершённой партии и подтверждает действие («Вы уверены?», A0119).

---

## 4. Основной поток

1. После подтверждения Фронтенд блокирует повторную отправку сдачи до ответа (A0131) и передаёт Бэкенду запрос по каналу партии реального времени (WebSocket, A0130).
2. Бэкенд проверяет, что партия ещё не завершена.
3. Бэкенд фиксирует `GAME_OVER` с победой Бэкенда (FT-077), в том числе если право хода было у Бэкенда.
4. Выполняется include UC-004 (запись статистики: +игра, +победа Бэкенда, учёт выстрелов партии в среднем).
5. Бэкенд оповещает Фронтенд о `GAME_OVER`.
6. Фронтенд показывает Игроку экран результата (A0118).
7. Дальнейшие выстрелы и повторная сдача в этой партии не принимаются как новый исход (FT-077).

---

## 5. Альтернативные потоки

### 5.1. Некорректные данные

**[Шаг 1.1]** Запрос сдачи без идентификатора сессии / с неверным типом полезной нагрузки.

1. Бэкенд отклоняет без `GAME_OVER`.
2. **Возврат** к экрану партии (если сессия ещё активна) или **завершение** с ошибкой запроса.

### 5.2. Timeout / недоступность

**[Шаг 1.2]** Бэкенд недоступен в момент сдачи.

1. Фронтенд сообщает о невозможности завершить выход на сервере.
2. Локальное закрытие UI **не** равно сдаче на Бэкенде (обрыв ≠ сдача).
3. Сессия остаётся активной до TTL (FT-074).
4. **Завершение** попытки UI; при восстановлении связи Игрок может повторить сдачу (шаг 1) или продолжить бой.

### 5.3. Прерывание

**[Шаг 0.1]** Игрок отменяет подтверждение «Вы уверены?» (A0119).

1. Запрос сдачи на Бэкенд не отправляется.
2. **Возврат** к экрану партии.

**[Шаг 1.3]** Обрыв соединения без явного выхода.

1. Это **не** данный UC: сдача не фиксируется.
2. **Завершение** без UC-004; далее UC-006 или TTL (FT-053).

### 5.4. Недостаточно прав

**[Шаг 2.1]** Запрос сдачи к чужой / неизвестной сессии.

1. Отказ без изменения чужого состояния (по аналогии с NFT-010 для мутаций).
2. **Завершение**.

**[Шаг 2.2]** Партия уже с `GAME_OVER`.

1. Повторная сдача не фиксируется (FT-077).
2. **Завершение** без новой записи статистики.

### 5.5. Конкурентный доступ

**[Шаг 2.3]** Одновременно выстрел Игрока / ход Бэкенда и сдача.

1. Бэкенд обеспечивает один итоговый `GAME_OVER` (см. UC-004 [Шаг 1.2]).
2. Если сдача принята — победа Бэкенда; статистика один раз.
3. **Завершение** через UC-004.

### 5.6. Граничные значения

**[Шаг 2.4]** Сдача на ходе Игрока — допустима (альтернатива выстрелу, US-005 AC3); основной поток с шага 3.

**[Шаг 2.5]** Сдача на ходе Бэкенда — допустима (A0092); основной поток с шага 3.

**[Шаг 3.1]** Сдача при нуле выстрелов в партии — статистика всё равно обновляется записью завершённой партии (среднее учитывает 0 выстрелов этой записи).

---

## 6. Потоки исключений

### E1. Сдача принята, оповещение Фронтенду не доставлено

1. Исход на Бэкенде зафиксирован (UC-004 выполнен).
2. При следующем соединении Игрок узнаёт, что партия завершена.
3. **Завершение** домена успешно; UI догоняет состояние.

### E2. Ложное принятие «закрытия окна» как сдачи

1. Требование: только явный выход = сдача. Случайное закрытие / kill процесса сдачей не считать.
2. Если реализация ошибочно вызвала FT-077 — дефект; корректное поведение — E путь 5.3.
3. **Возврат** к модели «обрыв ≠ сдача» после исправления.

---

## 7. Постусловие

**Успех:** `GAME_OVER` с победой Бэкенда; статистика обновлена один раз; Игрок уведомлён; обрыв без явного выхода таким исходом не считается.

**Отказ / обрыв:** партия может продолжаться; сдачи нет.
