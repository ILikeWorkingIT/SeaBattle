# UC-002: Выполнить выстрел по полю Бэкенда

**Статус артефакта:** `Согласовано`, 2026-08-25 (A0146)  
**Уровень:** user goal  
**Связанные US:** US-002  
**Связанные ФТ:** FT-007, FT-008, FT-017, FT-018, FT-019, FT-020, FT-021, FT-022, FT-023, FT-024, FT-044, FT-045, FT-046, FT-047, FT-048, FT-051, FT-055, FT-063, FT-070, FT-071, FT-072  
**Источники:** ТЗ §3.1, §3.3; A0011; A0089; A0099; A0102; A0114; A0146; A0116; A0124; A0125; NFT-001; NFT-006

**Связанные сценарии:** при `MISS` — UC-003; при уничтожении последней палубы флота Бэкенда — include UC-004.

---

## 1. Акторы

| Роль | Тип | Участие |
| --- | --- | --- |
| Игрок | Primary | Выбирает клетку и инициирует выстрел |
| Фронтенд | Supporting | Показывает координаты, отправляет выстрел по каналу партии, отображает результат |
| Бэкенд | Supporting | Принимает выстрел, меняет состояние, оповещает о результате |

---

## 2. Предусловие

- Игровая сессия успешно создана (UC-001 завершён успешно).
- Партия не завершена (`GAME_OVER` нет).
- У Игрока есть право хода.
- Фронтенд подключён к каналу партии реального времени для этой сессии.
- Координаты на экране — буквами текущего языка и числами 1–10; в состоянии — двухцифровой код столбец-строка.

---

## 3. Триггер

Игрок на своём ходе выбирает клетку поля Бэкенда и отправляет выстрел через Фронтенд.

---

## 4. Основной поток

1. Фронтенд блокирует повторный ввод/клик по клетке до ответа сервера (A0116) и передаёт выстрел Бэкенду по каналу партии реального времени с координатами клетки поля Бэкенда.
2. Бэкенд проверяет: канал корректен; партия активна; ход Игрока; клетка в [0..9, 0..9]; клетка ещё не проверена; выстрел не по полю Игрока; полезная нагрузка валидна.
3. Бэкенд применяет выстрел к полю Бэкенда и определяет результат: `MISS`, `HIT` или `SUNK` (при `SUNK` — статус последней палубы `SUNK`, периметр отдаётся как `MISS`).
4. Бэкенд обновляет историю выстрелов, сдвигает idle TTL и выставляет право хода: при `MISS` — Бэкенду; при `HIT`/`SUNK` — остаётся у Игрока.
5. Если уничтожена последняя палуба флота Бэкенда — дополнительно фиксируется `GAME_OVER` (include UC-004) в том же исходе, что и `SUNK`.
6. Бэкенд оповещает Фронтенд о результате выстрела и (при необходимости) о смене права хода / `GAME_OVER`.
7. Фронтенд отображает клетку по единому mapping (A0099, A0125): промах — «тире»; ранен — «звёздочка»; потоплен — «X»; буфер — «тире»; непроверенные — пустые. После ответа снимает блокировку ввода для следующего действия.

---

## 5. Альтернативные потоки

### 5.1. Некорректные данные

**[Шаг 1.1]** Полезная нагрузка без координат или с неверным типом (FT-070).

1. Бэкенд отклоняет запрос без изменения состояния.
2. Фронтенд показывает отказ (p95 ≤ 1000 мс — NFT-006).
3. **Возврат** к ожиданию хода Игрока (перед шагом 1); право хода не меняется.

**[Шаг 2.1]** Координата вне поля / вне [0..9, 0..9] (FT-045) или клетка уже проверена (FT-044) или выстрел по своему полю (FT-048).

1. Отклонение без изменения состояния.
2. **Возврат** к ожиданию хода Игрока.

### 5.2. Timeout / недоступность

**[Шаг 1.2]** Канал партии недоступен / ответ на выстрел не получен.

1. Фронтенд сообщает о сбое связи; состояние на Бэкенде не меняется от «потерянного» ответа клиента.
2. Сессия остаётся активной (обрыв ≠ сдача); возможен UC-006.
3. **Завершение** текущего попытки выстрела. После восстановления — снова шаг 1 при сохранении права хода.

### 5.3. Прерывание

**[Шаг 1.3]** Во время ожидания ответа Игрок явно сдаётся (UC-005).

1. На Бэкенде мутации упорядочены (A0124): применяется первая принятая; при уже принятом выстреле сдача идёт к новому состоянию / no-op при `GAME_OVER`; при первой сдаче выстрел отклоняется.
2. **Завершение** через UC-005 → UC-004 либо продолжение после принятого выстрела.

### 5.4. Недостаточно прав

**[Шаг 2.2]** Нет права хода (FT-046), партия уже `GAME_OVER` (FT-047), выстрел до завершения старта (FT-069), выстрел не по каналу партии (FT-055 → `SHOT_WRONG_CHANNEL`).

1. Бэкенд отклоняет без изменения состояния; при FT-055 — код `SHOT_WRONG_CHANNEL` и короткий текст (A0089).
2. **Возврат** к текущему экрану партии (или к постусловию отказа); состояние партии прежнее.

> Логина нет: «права» здесь — право хода и канал сессии, не RBAC.

### 5.5. Конкурентный доступ

**[Шаг 2.3]** Одновременные дополнительные запросы выстрела той же стороны после принятия первого (FT-051).

1. Первый принятый выстрел обрабатывается по основному потоку.
2. Остальные отклоняются без изменения состояния сверх уже применённого хода.
3. **Возврат** к шагу 6–7 основного потока для принятого выстрела.

### 5.6. Граничные значения

**[Шаг 3.1]** Выстрел в угловую клетку `00` или `99` — допустим, если клетка не проверена; дальше основной поток с шага 3.

**[Шаг 3.2]** `HIT` по многопалубному кораблю без полного уничтожения — право хода у Игрока; **возврат** к шагу 1 для следующего выстрела.

**[Шаг 3.3]** `SUNK` не последнего корабля — буфер как `MISS`; ход у Игрока; **возврат** к шагу 1.

**[Шаг 3.4]** `MISS` — ход переходит Бэкенду; после шага 7 — **завершение** UC-002 с передачей управления UC-003.

---

## 6. Потоки исключений

### E1. Выстрел с чужим / несуществующим идентификатором сессии

1. Бэкенд отклоняет без мутации любой сессии и без выдачи чужого состояния (NFT-010).
2. **Завершение** попытки; текущая легитимная сессия Игрока не затрагивается.

### E2. Внутренний сбой применения выстрела после валидации

1. Состояние либо применяется атомарно, либо откатывается; частичного «полувыстрела» Игрок не видит как успех.
2. Фронтенд получает отказ / ошибку операции.
3. **Возврат** к ожиданию хода Игрока (состояние согласовано) или **завершение** с предложением возобновить канал (UC-006).

---

## 7. Постусловие

**Успех (`MISS`):** клетка помечена; ход у Бэкенда; TTL сдвинут; Фронтенд оповещён; статистика не менялась (если не было `GAME_OVER`).

**Успех (`HIT`/`SUNK` без конца флота):** клетка(и) обновлены; ход у Игрока; TTL сдвинут; Фронтенд оповещён.

**Успех с концом флота:** выполнен UC-004 (победа Игрока).

**Отказ:** состояние партии не изменено этим запросом; Игрок информирован.
