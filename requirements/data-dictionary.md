# Словарь данных (Data Dictionary)

**Статус:** `Согласовано`, 2026-08-25 (A0161)  
**Дата:** 2026-08-25  
**Назначение:** атрибуты сущностей и объектов-значений Sea Battle (MVP PvE): обязательность, типы, ограничения, значения по умолчанию, граница MVP. Не контракт API и не схема СУБД.  
**Имена атрибутов:** английские идентификаторы доменной модели (`camelCase`).  
**Источники:** `glossary.md` (A0162), `diagrams/diagram-class-001.md` (A0148), `domain-model.md` (A0147), `functional-requirements.md`, UC-001…UC-008 (A0146), `answers-project.md` (в т.ч. A0149–A0152, A0161). НФТ использованы только для ограничений идентификатора и TTL (NFT-017, FT-005).  
**Приоритет фактов:** закрытые ответы `Axxxx` и согласованные ФТ важнее предварительного ТЗ.

Термины и коды (`MISS`, `HIT`, `SUNK`, `GAME_OVER`, Hunt Mode, Target Mode, игровая сессия, Бэкенд, Фронтенд) — по глоссарию.

## Соглашения

| Колонка | Смысл |
| --- | --- |
| Обязательность | **Да** — поле должно быть задано в каждом валидном экземпляре; **Нет** — допустимо отсутствие (пустое значение); **Условно** — обязательно при указанном условии |
| Тип | Бизнес-тип модели, не тип языка программирования. Перечисления — в §4 |
| Ограничения | min/max, длина, формат, enum, кратность. «Не зафиксировано» — решение отложено (обычно до API) |
| По умолчанию | Значение в момент создания экземпляра. «—» — значения по умолчанию нет (поле вычисляется, задаётся правилом или неприменимо) |
| MVP | **MVP** — нужно для согласованного MVP; **не MVP** — вне scope (логин, PvP, рейтинг и т.п.) |

Производные поля помечены в описании: их **не хранить отдельно**, если источник уже есть (например `CellCoordinate.code` из `column`+`row`).

В модели **нет** сущности «Игрок как учётная запись» (A0016). Доступ к партии — секрет `GameSessionId`.

## 2. Атрибуты по сущностям

### 2.1. Session

Игровая сессия = матч (A0010). Оперативное состояние: матрицы полей, история выстрелов, текущий ход (FT-002). Матрица вероятностей **не** входит.

**Обязательные:** `id`, `mode`, `status`, `turn`, `ttlAnchor`, `idleTtl`, `connected`, `playerBoard`, `backendBoard`, `playerFleet`, `backendFleet`, `shots` (набор может быть пустым).  
**Необязательные:** `winner`, `endReason` (только при `GameOver`).

| Атрибут | Тип | Обязательность | Ограничения | По умолчанию | MVP | Описание | Источник |
| --- | --- | --- | --- | --- | --- | --- | --- |
| id | GameSessionId | Да | Уникален; непрозрачная строка из 32 hex-символов (длина = 32, алфавит `[0-9a-fA-F]`, мощность 2^128) или иной генератор с мощностью ≥ 2^128; **не** UUID v4; неизвестный/недоступный id → единый отказ без различия причин | Генерируется при успешном старте (после выдачи расстановки Игроку) | MVP | Единственный ключ доступа к партии в MVP (логина нет) | FT-001, FT-067, A0016, A0048, A0149, NFT-017 |
| mode | GameMode | Да | Enum: только `PvE` | `PvE` | MVP | Режим партии. Иные режимы (PvP) в модель не входят | FT-043 |
| status | SessionStatus | Да | Enum: `Active` \| `GameOver` | `Active` | MVP | `GameOver` — момент фиксации конца; длительное хранение агрегата после доставки оповещения не требуется | FT-002, FT-025, A0142, A0145 |
| turn | Side | Да | Enum: `Player` \| `Backend` | `Player` | MVP | Право хода. Не путать с `Shot.seq` | FT-016, FT-022…FT-024 |
| winner | Side | Условно | Задаётся только при `status = GameOver`; при сдаче всегда `Backend` | нет значения (пока `Active`) | MVP | Победитель. При уничтожении флота — противоположная сторона | FT-026, FT-077 |
| endReason | EndReason | Условно | Enum: `FleetLost` \| `Surrender`; только вместе с `GameOver`. TTL и `SESSION_ABORTED` сюда не входят | нет значения (пока `Active`) | MVP | Причина конца партии | FT-053, FT-075, FT-077 |
| ttlAnchor | Метка времени | Да | Меняется только при создании сессии и при **принятом** выстреле. Возобновление, язык, статистика, отклонённый выстрел — не сдвигают. Хранение — момент времени в UTC; JSON — ISO-8601 `date-time` (A0158) | момент успешного создания сессии (UTC) | MVP | Якорь скользящего idle TTL | FT-005, A0144, A0150, A0158, UC-001 |
| idleTtl | IdleTtl | Да | Ровно 30 минут | 30 минут | MVP | Длительность окна бездействия | FT-005, FT-053 |
| connected | Логический | Да | Не более одного активного соединения на сессию | — (значение задаёт факт канала: есть соединение / обрыв). Отдельного литерала «по умолчанию при создании» в ФТ нет | MVP | Обрыв слот лимита не освобождает. Reconnect того же запуска замещает соединение, это не второй Фронтенд | FT-068, FT-074, A0133, UC-006 |
| playerBoard | Board | Да | Ровно одно; `owner = Player` | создаётся генерацией полей | MVP | Поле Игрока; выдаётся клиенту | FT-006, FT-014 |
| backendBoard | Board | Да | Ровно одно; `owner = Backend` | создаётся генерацией полей | MVP | Поле Бэкенда; палубы скрыты до `HIT`/`SUNK` | FT-015, NFT-009 |
| playerFleet | Fleet | Да | Ровно один; `owner = Player` | валидная расстановка | MVP | Флот Игрока; выдаётся после генерации | FT-009, FT-014 |
| backendFleet | Fleet | Да | Ровно один; `owner = Backend` | валидная расстановка | MVP | Флот Бэкенда целиком Игроку не выдаётся | FT-009, FT-015 |
| shots | набор Shot | Да | 0..N; `seq` уникален и строго возрастает | пустой набор | MVP | История принятых выстрелов | FT-002, UC-002, UC-003 |

**Производные (не хранить отдельно):** остаток idle TTL = `idleTtl` − (сейчас − `ttlAnchor`), неотрицательный (FT-080, `RemainTtl`); флот уничтожен ⇔ все 10 кораблей `Sunk`; число выстрелов партии = мощность `shots`.

**Не добавлять:** `createdAt` (дублирует первый `ttlAnchor`); `language` (A0091); `heatmap`; `playerId`; `gameOver` на сессии сверх `status`; отдельный TTL «завершённых».

| `SESSION_ABORTED` | сбой пустой heatmap при живом флоте Игрока (FT-076) | MVP |
| `SHOT_WRONG_CHANNEL` | выстрел не по каналу партии (FT-055) | MVP |

Создание сессии — ответ на запрос старта, без отдельного push-кода. Перечень оповещений партии — FT-036; вне перечня — TTL (FT-066) и `SESSION_ABORTED`.

## 5. Анализ расширений относительно диаграммы классов

### 5.1. Добавлено (было связью или только в доменной модели / ФТ)

### 5.2. Рассмотрено и не добавлено

| Кандидат | Решение |
| --- | --- |
| Session.createdAt | Дублирует первый `ttlAnchor` |
| Session.language / language на Бэкенде | Запрещено A0091, FT-062 |

| CellCode как отдельное хранимое поле | Производная `CellCoordinate.code` |

### 5.3. Вне MVP (сущностей в словаре нет)

- учётная запись Игрока, логин, роли;
- PvP и `GameMode` кроме `PvE`;
- ручная расстановка;
- рейтинг и персональная статистика;
- экран ввода id и сохранение `sessionId` на диск;
- Фронтенд на Linux/macOS как требование данных не описывается.
