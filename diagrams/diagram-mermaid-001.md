# Mermaid: ход Бэкенда и смена состояния партии (US-003)

**Тип:** flowchart  
**Источник:** [US-003](../requirements/user-stories/us-003-ai-turn-and-state.md); порядок шагов — [UC-003](../requirements/use-cases/uc-003-backend-turn-and-state.md)  
**Статус:** черновик для согласования  
**Связанные ФТ:** FT-027…FT-034, FT-036, FT-050, FT-052, FT-058, FT-064, FT-065, FT-075, FT-076, FT-079

---

## 1. Начало и концы

**Начало (триггер):** активная сессия; партия не завершена; право хода у Бэкенда → Бэкенд начинает ход (UC-003 §2–3).

**Концы одного прохода / серии:**

| Код | Постусловие |
| --- | --- |
| E-MISS | `MISS`; право хода у Игрока; Фронтенд оповещён (если на связи) |
| E-CONTINUE | `HIT`/`SUNK` без конца флота; ход у Бэкенда → повтор UC-003 с шага 1 |
| E-GO | `GAME_OVER`, победа Бэкенда (после выстрела или FT-052) |
| E-ABORT | Пустая heatmap, флот Игрока жив: `SESSION_ABORTED` → удаление сессии (FT-076 → FT-075) |

**Намеренно вне диаграммы** (есть в UC-003, не в AC основного среза US-003): сдача UC-005; idle TTL; обрыв Фронтенда при оповещении (UC-003 §5.2–5.3); отказ клиента без права хода (FT-046). Ограничения «heatmap и Hunt/Target не в UI» (FT-050, A0095) — в шаге оповещения и здесь, **без** отдельных узлов UI.

---

## 2. Шаги процесса

1. Определить режим: Hunt Mode или Target Mode; при нескольких раненых — добивать один корабль до `SUNK` (FT-079) — внутри Target, не отдельная развилка.
2. В Target Mode задать область (FT-058): один `HIT` — ортогональный крест; два+ на линии — продолжения оси; вне области веса обнуляются (правило внутри шага области).
3. Пересчитать матрицу вероятностей 10×10 (оставшиеся корабли, промахи, потопленные зоны).
4. Если нет клеток с весом > 0: выстрел не выполнять (FT-065) → проверка победы (FT-052) → `GAME_OVER` или `SESSION_ABORTED`.
5. Иначе выбрать клетку max веса; при равенстве — случайно из лидеров (FT-034, FT-064) — правило ничьей **в имени шага**, не ромб.
6. Выполнить выстрел → `MISS` / `HIT` / `SUNK`.
7. Обновить состояние и право хода (`MISS` → Игрок; `HIT`/`SUNK` → Бэкенд); при конце флота — `GAME_OVER` (UC-004).
8. Оповестить Фронтенд (выстрел Бэкенда, результат, смена хода / `GAME_OVER`); heatmap и режимы игроку не показывать.
9. При `HIT`/`SUNK` без `GAME_OVER` — возврат к шагу 1.

## 3. Точки ветвления (условия)

| # | Условие | Ветки | Источник |
| --- | --- | --- | --- |
| B1 | Есть раненый непотопленный корабль Игрока? | да → Target; нет → Hunt | AC2, UC-003 шаг 1 |
| B2 | В Target: один HIT или два+ на линии? | один → крест; два+ → ось | AC2, FT-058, UC-003 шаг 1.3 |
| B3 | Есть свободная клетка с весом > 0? | нет → пустая heatmap; да → выбор и выстрел | AC4, UC-003 шаг 2.2 |
| B4 | Флот Игрока уничтожен? (пустая heatmap) | да → `GAME_OVER`; нет → `SESSION_ABORTED` | AC4, FT-052 |
| B5 | Результат выстрела | `MISS` / `HIT` / `SUNK` | AC1, UC-003 шаг 4–5 |
| B6 | После `HIT`/`SUNK`: весь флот уничтожен? | да → `GAME_OVER`; нет → повтор хода | UC-003 шаг 5–6, 5.1 |

Не выделены ромбами: ничья весов; «добивать один корабль» при нескольких раненых; обнуление вне Target; скрытие heatmap в UI.

## 4. Диаграмма

```mermaid
flowchart TD
  Start([Старт: право хода у Бэкенда, партия не завершена]) --> B1{B1: раненый непотопленный корабль?}

  B1 -->|нет: Hunt Mode (B1)| Hunt[Hunt Mode: пересчёт heatmap по оставшимся кораблям]
  B1 -->|да: Target Mode (B1)| Target[Target Mode: добивать один корабль до SUNK]

  Target --> B2{B2: HIT текущего корабля?}
  B2 -->|один HIT: крест (B2)| AreaCross[Область: ортогональный крест; вне — вес 0]
  B2 -->|два и более на линии: ось (B2)| AreaAxis[Область: продолжения оси; вне — вес 0]
  AreaCross --> Recalc[Пересчитать матрицу вероятностей 10x10]
  AreaAxis --> Recalc
  Hunt --> Recalc

  Recalc --> B3{B3: есть клетка с весом больше 0?}

  B3 -->|нет: пустая heatmap (B3)| NoShot[Выстрел не выполнять]
  NoShot --> B4{B4: флот Игрока уничтожен?}
  B4 -->|да: победа Бэкенда (B4)| EndGO1([Конец E-GO: GAME_OVER])
  B4 -->|нет: сбой heatmap (B4)| Abort[SESSION_ABORTED RU/EN, затем удалить сессию]
  Abort --> EndAbort([Конец E-ABORT: сессия недоступна])

  B3 -->|да: есть клетка (B3)| Pick[Выбрать max вес; при ничьей — случайно из лидеров]
  Pick --> Shot[Выстрел по полю Игрока]
  Shot --> B5{B5: результат выстрела?}

  B5 -->|MISS: ход Игроку (B5)| NotifyMiss[Оповестить: выстрел Бэкенда, MISS, смена хода]
  NotifyMiss --> EndMiss([Конец E-MISS: ход у Игрока])

  B5 -->|HIT: ход у Бэкенда (B5)| AfterHit[Обновить состояние; ход остаётся у Бэкенда]
  B5 -->|SUNK: ход у Бэкенда (B5)| AfterHit
  AfterHit --> B6{B6: весь флот Игрока уничтожен?}
  B6 -->|да: GAME_OVER (B6)| NotifyGO[Оповестить: выстрел, результат, GAME_OVER]
  NotifyGO --> EndGO2([Конец E-GO: GAME_OVER])
  B6 -->|нет: серия ходов (B6)| NotifyCont[Оповестить: выстрел, HIT или SUNK, ход у Бэкенда]
  NotifyCont --> EndLoop([Конец E-CONTINUE: повтор хода Бэкенда])
  EndLoop -->|возврат к шагу 1| Start
```

**Проверено (§1.3):** шаги AC1–AC4 и UC-003 основной + 2.2/1.3/5.1 отражены или исключены с пометкой; у B1–B6 все исходы из источника; старт и финалы E-MISS / E-CONTINUE / E-GO / E-ABORT на схеме; внутренние фильтры без развилки не вынесены в ромбы; UI-экраны не моделировались; подписи стрелок — смысл + код ветки.
