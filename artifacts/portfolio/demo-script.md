# Сценарий показа на собеседовании (5–7 минут)

Запуск GUI из терминала агента Cursor окно на рабочий стол не выводит. Compose и клиент — в обычном PowerShell / проводнике. Разрешение на Docker — у вас.

На экране соперник подписан **Компьютер**.

## Подготовка (до звонка)

1. Из корня репозитория: `docker compose up --build` (Redis + API `:8000`).
2. Проводник → `src` → `run-frontend.bat` (Python 3.12+, `pip install -r src/frontend/requirements.txt`).
3. Запасная проверка API: браузер `http://localhost:8000/docs` или контракт через `requirements/run-openapi-docs.bat` (Swagger 8080 — это YAML-просмотрщик, Try it out живой только при поднятом backend).

## Живой рассказ

1. **Лобби (30 с).** Вкладки флота и правил MVP; меню языка RU/EN (UC-008, без запроса на сервер).
2. **Старт (40 с).** Новая игра → своё поле с кораблями, поле Компьютера без чужих палуб (UC-001, FT-015).
3. **Выстрел (1 мин).** Клик по полю Компьютера. Попадание — ход остаётся; промах — ход Компьютера, клетка на своём поле без ручного ввода (UC-002, UC-003).
4. **Флот (30 с).** Вкладка состава: статусы; у Компьютера тип после потопления, не заранее.
5. **Статистика (20 с).** Диалог KPI = `GET http://localhost:8000/statistics` (UC-007).
6. **Сдача или конец (40 с).** Либо «Сдаться» с подтверждением (UC-005), либо короткий комментарий про `GAME_OVER` и слот (UC-004). REST-сдачу не показывать игроку; при вопросе архитектора: `POST …/surrender` → 400, партия жива.
7. **Reconnect (1 мин, если есть время).** Не закрывая окно: `docker compose stop backend` → сообщение о связи; `docker compose start backend` → партия продолжается, TTL не «сбрасывается» на 30:00 (UC-006). Полный перезапуск `.bat` сессию не подхватывает (A0093).

## Чего не обещать

Лимит трёх сессий удобно показать **двумя–тремя** окнами, не четырьмя историями в одном. Idle 30 минут вживую не ждать: сослаться на кадр `ttlExpired` и тесты.

## Если Docker нельзя

Показать код слоёв + OpenAPI + диаграммы C4/sequence из `diagrams/`. Окно без API стартует, живая партия — нет.
