# Кейс: Sea Battle (MVP PvE)

**Роль в витрине:** системный аналитик + архитектор решения.  
**Статус продукта:** рабочий MVP (срезы S-00…S-08 закрыты, 2026-09-17).  
**Автотесты:** 279 passed (`reports/test-run.md` на дату закрытия S-08).

## Задача

Собрать клиент–серверный «Морской бой»: человек играет против серверного ИИ, без логина и без PvP. Нужны проверяемые правила боя, скрытие чужого флота, канал партии в реальном времени и глобальная статистика сервера — не игрушка в одном процессе.

Проект одновременно инженерный полигон: пакет требований (ФТ/НФТ, US/UC, DDD, OpenAPI) и код в слоях Clean Architecture.

## Границы MVP

Входит: десктоп PySide6; API FastAPI; Redis; REST для старта и статистики; WebSocket для выстрела, сдачи, снимка и reconnect; авторасстановка обоих флотов; Heatmap Hunt/Target на сервере; idle TTL 30 минут; не более трёх активных сессий; RU/EN только на клиенте.

Не входит: PvP, учётная запись, ручная расстановка, персональная статистика, показ heatmap игроку, возобновление партии после полного перезапуска приложения.

## Стек (факт репозитория)

Python 3.12+, FastAPI + Uvicorn, Redis 7, PySide6, Docker Compose (`redis` + `backend` на порту 8000), pytest.

## Роль автора

Заказчик и исполнитель — один человек. Аналитика и архитектура зафиксированы в `requirements/` и `diagrams/` до и вместе с кодом. Разработка шла срезами по UC с гейтом качества. Оболочка агентов Cursor (MAS) — способ работы, не предмет витрины продукта.

## Решения, которые стоит разобрать на интервью

1. **Выстрел только по WebSocket.** REST `POST /sessions/{id}/shots` и REST-сдача отвечают отказом; состояние партии не меняется (A0089, OpenAPI).
2. **ИИ без ML.** Ход Бэкенда — матрица вероятностей Hunt/Target; игроку отдаются только клетки и результат, не веса (A0014, A0095).
3. **Слоты.** Атомарный захват слота при успешном старте; лимит 3; слот снимается сразу при `GAME_OVER` (A0081, A0128).
4. **Idle TTL.** 1800 с; reconnect **не** сдвигает якорь; истечение — кадр `ttlExpired`, не `GAME_OVER` и не запись в журнал.
5. **Журнал.** HASH счётчиков + LIST записей; одна запись на `sessionId` (A0129).
6. **Секрет доступа** — идентификатор сессии; второго живого WS на тот же id нет (A0002).
