# Контроль качества ФТ и НФТ

Прочитай и выполни `.cursor/skills/skill-quality-control-ft-nft.md` целиком. Команда `/qc-ft-nft` запускает этот скилл.

Скиллы написания (`skill-ft`, `skill-nft`) — только канон формы: не выполняй их алгоритмы и не вызывай `/ft` / `/nft` «заодно».

## Ввод

`$1` и дальнейший текст — уточнение: пути к ФТ/НФТ, глоссарию, ТЗ; чьи ответы обработать; куда сохранить отчёт; только ФТ / только НФТ.

Если текста нет — проверь файлы, которые **есть** в проекте (`requirements/functional-requirements.md` и/или `requirements/non-functional-requirements.md`). Отчёт пиши в `reports/incompatibility-ft-nft.md`. Отсутствие одного файла не дефект, пока пользователь не просил совместный аудит.

## Какой режим

Смотри на ввод, отдельную подкоманду выбирать не нужно.

- **Отчёт без правок** (шаги 1–2 скилла) — нет ответов по строкам отчёта и нет фраз вроде «внеси», «обработай ответы», «согласен» по пунктам QC. Типично: пустой `/qc-ft-nft`, «проверь ФТ/НФТ», «аудит». Файлы требований не меняй.
- **Перенос ответов** (шаг 3 скилла) — в чате или в колонке «ответ» отчёта уже есть ответы / «да» / «согласен» / «сделай рекомендацию», либо явно сказано обработать ответы. Внеси правки и `Axxxx`; повторный `/qc-ft-nft` по тем же правкам не предлагай.

Если в одном сообщении и «проверь», и ответы — сначала перенеси ответы (шаг 3), новый полный аудит не начинай, пока пользователь его явно не попросил.

## После выполнения

Кратко: путь отчёта, число строк по приоритетам, критичные ID. Не повторяй таблицу.

- Аудит без ответов: файлы ФТ/НФТ не меняй.
- В запросе есть ответы или согласие на правки: внеси по шагу 3 скилла. Не предлагай и не запускай повторный `/qc-ft-nft` по тем же правкам.
