# Написать или обновить словарь данных

Прочитай и выполни `.cursor/skills/skill-data-dictionary.md` целиком. Команда `/data-dictionary` запускает этот скилл.

Заключительный этап скилла **обязателен:** проверка по гейту §7 того же скилла **до** сообщения разработчику, что файл создан или обновлён. Любая запись в файл словаря (создание, правка, перенос ответов) заканчивается §7. Пропуск гейта = работа не завершена. Не больше двух проходов «гейт → правка → гейт» за запуск.

## Ввод

`$1` и дальнейший текст — уточнение: путь к глоссарию, диаграмме классов, доменной модели, ФТ, UC; создать или обновить `data-dictionary.md`; только проверка существующего файла; «только отчёт без правок»; чьи ответы по DD-Q обработать.

Если текста нет — построй или обнови словарь по текущим документам проекта, затем сразу §7. Нет ни диаграммы классов, ни доменной модели с списком сущностей — **не** выдумывай словарь в этом ходе: зафиксируй пробел и спроси с рекомендацией.

Если запрос — только «проверь словарь» без написания с нуля — **не** создавай второй файл: выполни §7 по существующему `requirements/data-dictionary.md` (или пути пользователя). Нет файла — сообщи о пробеле, не создавай молча, если не просили создать.

Не применяй эту команду вместо `/ddd` или `/diagram-mermaid` / `/diagram-bpmn`, если нужна только модель или только схема без каталога полей. Не применяй вместо `/ft` / `/uc`, если задачи про словарь нет.

## После выполнения

Кратко: путь к файлу, статус, покрытие классов (диаграмма или модель), открытые DD-Q, факт прохождения гейта §7 (или остановка по лимиту). Не дублируй все таблицы в чат. Не утверждай пакет без явного согласия заказчика.
