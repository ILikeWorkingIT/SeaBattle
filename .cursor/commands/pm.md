# Точка входа MAS — Project Manager

Прочитай и выполни `.cursor/skills/skill-agent-pm.md` целиком, затем `.cursor/agents/agent-pm.md`. Команда `/pm` запускает роль `pm`.

`/pm` **не** гоняет все документы проекта подряд и **не** подменяет несуществующий `/full-cycle`. Пустой вызов — статус и предложение **одного** среза из `reports/checklist.md`. После фразы запуска («запускай S-NN») ПМ **сам** запускает конвейер этого среза (бэк → тесты → фронт → тесты → гейт). Пользователь не обязан вводить команды исполнителей. Голое «согласен» без среза не стартует конвейер.

## Цель этапа

Сверить `reports/project-config.md`, `reports/pm-state.md`, `reports/checklist.md`. Выбрать первый незакрытый срез. По режиму: только предложить **или** вызвать исполнителей. Код и требования сам не пиши.

## Роль-исполнитель

`pm` (`.cursor/agents/agent-pm.md`).

## Input manifest

- `reports/project-config.md`
- `reports/pm-state.md`
- `reports/navigator.md`
- `reports/checklist.md`
- `.cursor/list-commands.md`
- `documentation/` (стек и MAS; канон ТЗ — `documentation/specification-sea-battle-v1-1.md`; не выдумывай `Specification.md`, если файла нет)
- шаблоны: `reports/templates/project-config.template.md`, `reports/templates/pm-state.template.md`

## Skill(s)

`.cursor/skills/skill-agent-pm.md`

## Output artifact(s)

- `reports/project-config.md` — создать с нуля только если файла нет. Существующие уникальные поля не затирать.
- `reports/pm-state.md` — создать, если нет; иначе обновить `stage-id` / `status` / очередь по режиму ниже.
- `reports/checklist.md` — создать под этот продукт, если файла нет; чужой чеклист не копировать.

## Review manifest

Конвейер среза — обязанность ПМ: исполнители по скиллам `/app-layer`, `/new-tests`, `/use-tests`, `/frontend`, `/qc-stage` **по очереди**, без поручения пользователю набрать эти команды. Просить ручную приёмку только при PASS в `reports/test-run.md` и гейт без critical/major. Код, тесты и прогон — разные ходы.

## Gate checklist

- Стек в `project-config.md` взят из фактов репозитория, не из догадок.
- `stage-id` совпадает с командой из `list-commands.md` или с заголовком среза в чеклисте.
- `APPROVED` не ставится без фразы «утверждаю» / «принимаю этап» / «срез согласован».

## Update traceability

Не заполняй `reports/traceability.md` выдуманными commit ref. Если связей нет — оставь таблицу и напиши, чего не хватает.

## Ввод

`$1` и дальнейший текст — что делать: срез (`S-05`), команда (`app-layer`), «статус», «утверждаю».

Если текста нет — **статус**: первый незакрытый срез в `checklist.md`, что уже сделано, сценарий будущей проверки. Код не пиши. Конвейер не запускай.

## Какой режим

- **Статус** — пустой `/pm`, «что дальше». Отчёт в чат. Спросить запуск: `Запускай S-NN`. Не писать «введите `/app-layer`».
- **Старт / конвейер** — «запускай S-NN», «запускай срез», «да, запускай срез» сразу после предложения. `stage-id` вида `S-05` (срез, не сценарий S5). `in-progress`. Дальше **сам** конвейер по `skill-agent-pm`. Новый чат с `pm` и «Запускай S-NN» — старт конвейера, не статус. Голое «согласен» без id — уточнить (срез или QC/документ).
- **Утверждение** — «утверждаю» / «принимаю этап» / «срез согласован». `Stage: <id>: APPROVED` и `[x]` в чеклисте. Следующий срез только предложить.

Нет `/full-cycle` на весь пакет документов. Нет `/backlog-sync`, `/commit-audit` — не имитируй их. Прямые slash — сценарий S5.

## После выполнения

Статус: срез, очередь, ждёшь ли согласия. После конвейера: PASS/FAIL, путь `test-run.md`, сценарий проверки окна. Не оставляй пользователя со списком команд «наберите сами».
