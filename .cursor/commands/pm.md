# Точка входа MAS — Project Manager

Прочитай и выполни `.cursor/skills/skill-agent-pm.md` целиком, затем `.cursor/agents/agent-pm.md`. Команда `/pm` запускает роль `pm`.

`/pm` **не** запускает все роли подряд и **не** подменяет `/full-cycle` (этой команды нет). Один вызов — инициализация состояния и **один** следующий шаг оркестрации, либо только статус, если текста нет.

## Цель этапа

Поднять или сверить `reports/project-config.md` и `reports/pm-state.md`, выбрать следующий `stage-id`, назначить исполнителя и существующую slash-команду. Код и требования сам не пиши.

## Роль-исполнитель

`pm` (`.cursor/agents/agent-pm.md`).

## Input manifest

- `reports/project-config.md`
- `reports/pm-state.md`
- `reports/navigator.md`
- `reports/checklist.md` (если есть)
- `.cursor/list-commands.md`
- `documentation/` (стек и MAS; канон ТЗ — `documentation/specification-sea-battle-v1-1.md`; не выдумывай `Specification.md`, если файла нет)
- шаблоны: `reports/templates/project-config.template.md`, `reports/templates/pm-state.template.md`

## Skill(s)

`.cursor/skills/skill-agent-pm.md`

## Output artifact(s)

- `reports/project-config.md` — создать с нуля только если файла нет. Существующие уникальные поля не затирать.
- `reports/pm-state.md` — создать, если нет; иначе обновить `stage-id` / `status` / очередь по режиму ниже.

## Review manifest

После того как исполнитель сдал артефакт — `/qc-stage`. Не в том же ходе, что написание кода среза, если пользователь не просил сразу гейт уже готового пакета.

## Gate checklist

- Стек в `project-config.md` взят из фактов репозитория, не из догадок.
- `stage-id` совпадает с командой из `list-commands.md` или с заголовком среза в чеклисте.
- `APPROVED` не ставится без фразы «утверждаю» / «принимаю этап».

## Update traceability

Не заполняй `reports/traceability.md` выдуманными commit ref. Если связей нет — оставь таблицу и напиши, чего не хватает.

## Ввод

`$1` и дальнейший текст — что делать: срез (`S-05`), команда (`app-layer`), «статус», «утверждаю».

Если текста нет — **статус**: проверь файлы, найди первый незакрытый срез в `checklist.md` (если файла нет — опирайся на `navigator.md`), предложи `stage-id` и команду. Код не пиши. `/qc-stage` не запускай.

## Какой режим

- **Статус** — пустой `/pm`, «что дальше», «статус». Отчёт в чат. `pm-state.md` можно оставить `idle` или записать предложенный `stage-id` без смены глобального этапа, если пользователь ещё не согласился.
- **Старт этапа** — в запросе есть id среза или имя команды. Запиши `stage-id`, `status: in-progress`, исполнителя. Дальше укажи существующую команду (`/app-layer`, `/frontend`, …) и **выполни её скилл в этом ходе только если** пользователь явно попросил сделать срез / работу, а не только спланировать. Иначе остановись после плана и спроси подтверждение.
- **Утверждение** — в запросе «утверждаю» / «принимаю этап». Запиши `Stage: <текущий-id>: APPROVED`. Следующий глобальный этап не начинай в том же ходе, если пользователь не указал какой.

Нет `/full-cycle`, `/backlog-sync`, `/commit-audit` — не имитируй их.

## После выполнения

Кратко: пути `project-config.md` и `pm-state.md`, `stage-id`, статус, кого назначить, какую команду вызвать дальше. Если ждал подтверждения — так и напиши.
