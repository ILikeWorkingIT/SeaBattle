# Прогон автотестов

Универсальный скилл. Не подставляй факты другого проекта.

Роль: тестировщик. Гоняешь набор **сам**, пишешь отчёт. Не пишешь новые тесты (`skill-new-tests` не запускай).

---

## Редирект

| Запрос | Действие |
| --- | --- |
| Только написать тесты, без прогона | Остановись. Нужна `/new-tests`. |
| Нет файлов тестов и нет команды раннера | Не выдумывай набор. Предложи `/new-tests`. |

---

## Бюджет (антипетля)

На **один** запуск скилла:

| Лимит | Значение | Если исчерпан |
| --- | --- | --- |
| Попыток фикса на один `BUG-…` | **2** | `стоп-лимит` |
| Прогонов **полного** набора (включая первый) | **4** | Больше полный набор не гоняй |
| Повторов той же команды после kill по таймауту | **0** | Тип `env` или `test_defect` |

**Запрещено:** watch-режим. Только одноразовый прогон. Не открывай GUI.

---

## SOP

### 0. Режим (один)

| Режим | Когда | Что делать |
| --- | --- | --- |
| **прогон** | `/use-tests`, «прогони» | §1–§5. Код не трогай |
| **прогон и исправление** | есть «исправь» | §1–§5, затем §6 |
| **повтор** | «перепрогони» | §1–§5; фикс только если снова сказали «исправь» |

### 1. Команда запуска

Агент запускает тесты **сам**. Пользователя не проси.

Порядок: README (если pytest, не запуск GUI) → `python -m pytest` в каталоге `tests/`. Не `test-data/`.

Команда, которая открывает окно приложения — не запускай.

Нет ни файлов, ни раннера — стоп, предложи `/new-tests`. **0 collected** — не PASS.

### 2. Первый прогон

Весь набор, пока пользователь не сузил путь. pytest `--tb=short`. Unit без новой строки **120 с** — убей. Весь прогон **10 мин** — убей. Сырой лог в чат не копируй.

### 3. Классификация

| Тип | Когда | Фикс в этом скилле |
| --- | --- | --- |
| `product_bug` | эталон = ФТ/US/UC/`Axxxx`/OpenAPI, код иначе | да, только режим исправления |
| `test_defect` | ложный эталон, GUI, `sleep` | нет. Предложи `/new-tests` |
| `env` | нет Redis/зависимости/порта | нет. Напиши, чего не хватает |
| `unknown` | лога мало | один verbose-повтор этого теста; максимум три за запуск |

### 4. Файл `reports/test-run.md`

Перезапиши целиком. Шапка: дата-время; точная команда; OS; итог цифрами; режим.

Очередь:

| ID | Тест | Файл теста | Тип | Воспроизведение | Ожидание | Факт | Требования | Где чинить | Доказательство | Статус |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

ID: `BUG-001`…. Доказательство: 3–8 строк traceback. Статус: `открыт` | `исправлен` | `не баг` | `нужна среда` | `стоп-лимит`.

### 5. Чат (не лог)

Не больше 8 строк (исправление — до 10). Ноль traceback.

Вердикт: PASS или FAIL  
Команда: (одна строка)  
Итог: N passed, M failed, K error, S skipped  
Продукт: до трёх `BUG-id`  
Отчёт: `reports/test-run.md`  
Дальше: при `product_bug` в режиме прогон — «запусти `/use-tests` исправь»; пустой набор — `/new-tests`.

### 6. Исправление (только этот режим)

Только `product_bug` + `открыт`. На каждый баг: изолируй → мини-правка продукта → перепроверь этот тест → соседи. Полный набор — один раз в конце, если лимит не исчерпан. Тесты не ослабляй.

---

## Запрещено

- Зелёный отчёт без запуска.
- Watch / GUI вместо раннера.
- Третья правка того же бага; полный набор после каждого бага.
- Выполнять `skill-new-tests`; чинить продукт в режиме **прогон**.
