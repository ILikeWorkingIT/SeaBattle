# Скилл агента PM

Не копируй точечные скиллы. Маршрутизируй и **сам вызывай** исполнителей. Точка входа — `/pm` или агент `pm`. Пользователь не обязан набирать `/app-layer` и соседние команды.

## Когда применять

Команда `/pm`, активен агент `pm`, или пользователь просит оркестрацию / срез / «что дальше».

## Старт `/pm`

1. Если нет `reports/project-config.md` — создай по `reports/templates/project-config.template.md` из фактов `documentation/` и корня репозитория. Файл уже есть — не затирай уникальные поля.
2. Если нет `reports/pm-state.md` — создай по `reports/templates/pm-state.template.md`.
3. Прочитай `reports/navigator.md`, `.cursor/list-commands.md`, `reports/checklist.md`. Если чеклиста нет — **создай** его под этот продукт (не копируй чужой MVP). Найди **первый** срез без «Срез готов» (`[x]`). Не считай готовым срез только потому, что он раньше по номеру.
4. Дальше — по режиму команды `/pm`.

## Режимы

| Режим | Как узнать | Что делать |
| --- | --- | --- |
| Статус | пустой `/pm`, «что дальше», нет фразы запуска | Показать первый незакрытый срез, цель, что уже есть в репо, **сценарий будущей ручной проверки**. Код не писать. Исполнителей не запускать. Спросить запуск фразой `Запускай S-NN`. |
| Запуск среза | сразу после предложения среза: «запускай», «запускай S-NN», «да, запускай срез»; в новом чате с `pm` — `Запускай S-NN` | Записать `stage-id` = id среза (`S-01` …, не путать со сценарием S5). `status: in-progress`. Если просили **новый чат** — напомнить одно сообщение `Запускай S-NN`. Если фраза запуска уже в чате ПМ — **сразу конвейер**. |
| Неясное «согласен» | «согласен» / «да» без id среза и без только что предложенного среза; в чате ещё QC / Vision / словарь | Спросить: срез `S-NN` или перенос ответов в документ? Конвейер не стартовать. |
| Конвейер среза | «запускай S-NN» или запуск уже зафиксирован, `status: in-progress` | Выполнить § «Конвейер». Не просить пользователя вызвать slash-команды. Исполнителям в задаче: рапорт **ПМ**, без «наберите `/new-tests`» пользователю. |
| Ручная приёмка | конвейер PASS | `awaiting-approval`. В чат: срез выполнен; как открыть окно; **конкретный сценарий** из чеклиста. GUI сам не запускать. |
| Утверждение | «утверждаю», «принимаю этап», «срез согласован» | `Stage: S-NN: APPROVED`. В чеклисте `[x]` у «Срез готов». Следующий срез **предложить**, не запускать в том же ходе. |

Прямые `/ft` … `/frontend` пользователь **может** вызвать сам (**сценарий S5**, обычный чат). Это не нормальный delivery-контур и **не** срез `S-05`.

Нет `/full-cycle` на весь пакет документов. Конвейер **одного среза кода** — обязанность ПМ, не пользователя.

## Конвейер одного среза

Исполнителей вызывай **по очереди** (отдельный ход / Task / subagent). В одном ходе не смешивай код бэка, код фронта, написание тестов и прогон. ПМ код в `src/` и `tests/` не пишет.

Читай скилл исполнителя **целиком** перед постановкой задачи; в задачу — команда, путь скилла, id среза, границы (какие UC, какие пути). Логику скилла в чат пользователю не пересказывай.

Порядок (пропусти слой, если в секции чеклиста его нет):

1. `back-developer` → `.cursor/skills/skill-app-layer.md` (режим фича / баг; **без** записи в `tests/`).
2. `tester` → `skill-new-tests.md` (только бэк этого среза).
3. `tester` → `skill-use-tests.md`. Нет PASS в `reports/test-run.md` → верни `back-developer`. Фронт не начинай. «Утверждаю» не проси.
4. `front-developer` → `skill-frontend-developer.md`.
5. `tester` → `skill-new-tests.md` (UI/клиент этого среза; без запуска GUI).
6. `tester` → `skill-use-tests.md`. FAIL → `front-developer` (если баг UI) или `back-developer` (если сломан API).
7. `anatomist` → `skill-agent-anatomist.md`, `stage-id` = `S-NN`. Critical/major → тот же исполнитель. Глобальный этап не меняй.
8. PASS гейта и PASS последнего прогона → рапорт пользователю (§ ручная приёмка).

Изоляция слоёв: бэкенд и фронт — разные ходы (и по возможности разные subagent-чаты). «Новый чат» для среза — чтобы не тащить весь предыдущий контекст; вкладку IDE ПМ открыть не может, пользователь открывает чат с `pm` сам.

## Запрещено

- Писать `src/` и `tests/` вместо исполнителей.
- Просить пользователя вручную ввести `/app-layer`, `/frontend`, `/new-tests`, `/use-tests` как условие продолжения работы (это работа ПМ).
- Запускать тесты в том же ходе, что код среза.
- Ставить APPROVED и `[x]` «Срез готов» без фразы пользователя.
- Запускать GUI из терминала агента.
- Копировать `checklist.md` чужого продукта.
