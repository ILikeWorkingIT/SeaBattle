# Создание автотестов

Универсальный скилл. Не подставляй факты другого проекта.

Роль: тестировщик. Цель: закрыть пробелы автотестами по канону. Не цель: прогон, фикс продукта.

Скилл **не** запускает `skill-use-tests` и **не** выполняет тесты.

---

## Редирект

| Запрос | Действие |
| --- | --- |
| Только прогон / «исправь падения» | Остановись. Нужна `/use-tests`. |
| Нет ни требований, ни эталона в чате / `@` | Не выдумывай. Спроси с рекомендацией. |
| Post-MVP без явного расширения | Не пиши тесты «для полноты». |

---

## SOP

Пустой `tests/` — не стоп: старт с pytest и именами `test_should_<поведение>_when_<условие>`.

### 0. Режим (один)

| Режим | Когда | Файлы |
| --- | --- | --- |
| **дополнение** | «напиши тесты», `/new-tests` | Пиши пробелы |
| **инвентаризация** | «каких тестов не хватает», без «напиши» | Не создавай файлы |
| **устаревшие** | канон сменился | Правь ложные эталоны, не плоди сценарии |

### 1. Канон

Приоритет: запрос → `Axxxx` → ФТ/НФТ/US AC/UC → OpenAPI → ТЗ → код (что можно вызвать).

### 2. Инвентарь

Ищи `tests/`, `conftest.py`, `tests/coverage.md`. Дубли не добавляй.

### 3. Пробелы

Слои: `happy` / `edge` / `negative`. Для UI дополнительно состояние: `empty` / `loading` / `error` / `disabled` / `success` / `dialog` / `—`.

Покрывай и **API** (pytest-asyncio, httpx/ASGI, мок Redis), и **клиент** (обработчики/состояние без живого окна), по тому, что в scope запроса.

### 4. Раннер и поверхность

По `src/`:

- Есть `src/backend/` — тесты API/домена без поднятия GUI.
- Есть `src/frontend/` — тесты без `QApplication.exec` / `mainloop`. Не открывай окно.
- Живой Redis/Docker в тесте не обязателен: мокай порт, если в репо ещё нет тестового контейнера и пользователь его не просил.

Раннер по умолчанию: `python -m pytest`. Зависимости в этом запуске не добавляй молча; в отчёте напиши, что поставить. Набор **не гоняй**.

Сеть и внешние системы в тесте не вызывай вживую (кроме явной просьбы). `sleep` запрещён.

Селекторы UI: `objectName` / `self.*` / подпись канона. HTML `data-testid` не ставь на Qt.

Не используй `test-data/` без прямого задания.

### 5. Карта

Обнови `tests/coverage.md`: Тест | Файл | Требования | Слой | Состояние UI | Примечание.

### 6. Гейт

- Один тест — один исход; ID требования в docstring.
- Нет GUI в тесте.
- Нет секретов.
- Прогон не выполнен в этом ходе.

## После выполнения

Кратко: пути, сколько тестов, какие ID закрыты, какие пробелы остались. Предложи `/use-tests`, не запускай.
