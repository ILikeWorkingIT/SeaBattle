# Чеклист срезов MVP — Sea Battle

Источник порядка бэкенда: `.cursor/skills/skill-app-layer.md` (UC-001 → UC-007 → UC-002+WS → UC-003 → UC-004 → UC-005 → UC-006; UC-008 только фронт).
Пакет требований и макет окна уже есть; этот файл — только **код и проверка** по срезам.

## Как работать (роль пользователя)

1. ПМ предлагает **один** незакрытый срез (первый без «Срез готов»).
2. Пользователь запускает срез: «запускай S-NN» / «да, запускай срез». Голое «согласен» без номера ПМ уточняет (срез или правки QC/документа).
3. Пользователь **не** набирает `/app-layer`, `/frontend`, `/new-tests`, `/use-tests`.
4. ПМ в **новом чате** с агентом `pm` сам запускает конвейер среза (подчинённые роли — изолированными ходами).
5. Когда автотесты PASS и гейт без critical/major, ПМ пишет: срез выполнен; **сценарий ручной проверки** (окно через `src/run-frontend.bat`, сервер — Compose по README).
6. Пользователь проверяет окно сам. Затем: «утверждаю» / «срез согласован» — можно следующий срез.
7. ПМ ставит `[x]` у «Срез готов» **только** после этой фразы.

Конвейер одного среза (слои по очереди, не в одном ходе исполнителя):

1. `back-developer` (`skill-app-layer`) — если в срезе есть сервер
2. `tester` (`skill-new-tests`) — тесты бэка
3. `tester` (`skill-use-tests`) — прогон; FAIL → вернуть бэкендера, не звать фронт
4. `front-developer` (`skill-frontend-developer`) — если в срезе есть клиент
5. `tester` (`skill-new-tests`) — тесты фронта (без `QApplication.exec`)
6. `tester` (`skill-use-tests`) — прогон
7. `anatomist` (`skill-agent-anatomist`, `/qc-stage`) — гейт среза `S-NN`
8. Рапорт ПМ + сценарий проверки окна

ПМ **не** запускает GUI из своего терминала.
